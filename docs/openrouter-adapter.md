# Historical OpenRouter provider adapter

Superseded by the [OpenAI-compatible Modal adapter](openai-compatible-adapter.md). This document records the earlier fixed-provider implementation; current configuration uses `OPENAI_BASE_URL`, `OPENAI_API_KEY` and `OPENAI_MODEL`.

Steps 3–5 are integrated. The adapter is the only generation provider, and supplied-value inputs are enabled. Validated original output is persisted and executed through [saved Compose execution](saved-compose-runtime.md). Legacy generation/compiler code has been removed. Public status identifies each job's provider/model. No live inference was performed during implementation.

## Configuration and request boundary

The operator supplies `OPENROUTER_API_KEY` to the API process. The secret-free root `.env.example` documents an empty placeholder, and `infra/docker-compose.yml` supplies it to API generation and to runner for explicitly invoked terminal evaluation. The development override inherits these settings. It is not passed to web, infrastructure MySQL, Docker child processes or generated workloads. Source development uses an exported process variable; no adapter code imports dotenv, reads environment files, configures credentials, or makes a startup inference request. Recreate API/runner after changing their Compose configuration. An absent/blank key produces `PROVIDER_NOT_CONFIGURED` when called, without making an HTTP request; missing credentials do not block application startup.

`OpenRouterGenerationProvider` implements the typed `ComposeGenerationProvider` seam, a specialization of the existing `GenerationProvider`. The worker calls this typed boundary directly. It never parses a generated intermediate service specification or renders Compose. A database-independent evaluator can reuse the same provider.

The adapter calls only `POST https://openrouter.ai/api/v1/chat/completions`, with bearer authentication, `model: google/gemma-4-26b-a4b-it:free`, non-streaming output, temperature `0.2`, and `max_tokens: 16384`. Provider price ceilings for prompt, completion, and per-request pricing are zero. There is no alternative model, router, model fallback list, tool, plugin, or response-healing request. Redirects are rejected so the credential cannot follow a redirected request.

Prompt version 2 includes the pinned catalog, version 2 policy constants, exact resource/service labels, server-owned identities, selected services, instructions, and environment references/purposes/assignments. The prompt requests the complete runtime-ready document directly, including service behavior, health checks, bindings, isolation, resource limits, and storage. It forbids published ports under the accepted private-only policy and explicitly describes arbitrary-character supplied values. It does not contain starter commands or generated Compose. Explicit field selection strips private extra properties from the root, identity, services, references, and bindings. Actual supplied values and original request-local value keys are excluded. Instructions and purposes are intentionally model-visible; users must keep credentials out of those text fields.

## Limits and returned metadata

Every provider call has a five-minute maximum and honors an earlier caller deadline/cancellation. Product orchestration shares one five-minute deadline across both content responses and all HTTP retries. Fetch, response reads, and retry waits are bounded; cancellation releases response streams, including late responses from an injected transport. Timers and abort listeners are removed after completion.

The JSON response body is limited to 8 MiB to accommodate JSON escaping and metadata; the extracted document is limited to 1 MiB of UTF-8. Invalid UTF-8/JSON, malformed schemas, multiple choices, tool calls, empty content, and incomplete finishes are rejected. A `length` finish is `OUTPUT_TRUNCATED`. Completed content is returned exactly as supplied, including whitespace and final newline. Fenced or unsafe YAML is still untrusted at this seam: it must reach the step 4 validator before persistence or execution.

Results include `provider: openrouter`, the requested model, the reported model, elapsed time, HTTP attempt count, and available nonnegative integer prompt/completion/total token usage. Unavailable usage is omitted. The response may report the same base model slug without `:free`; that exact slug is retained as reported metadata, while the request still pins the free route and zero price ceilings. Every other reported model is rejected. Extra provider fields and raw error details are discarded; API-key and value data are never logged by this module. Step 4 persists this safe metadata privately; public status identifies the selected provider/model without raw response details.

Network failures, HTTP 408/429/5xx, and matching numeric error envelopes in HTTP 200 responses permit at most two transient retries: three HTTP attempts per content request. Ordinary backoff is 500 ms then 1000 ms. Valid `Retry-After` seconds/dates are honored; a wait above 30 seconds fails explicitly instead of retrying early. All waits share the generation deadline. Authentication, credit, missing-model, and other permanent errors fail immediately. Safe codes distinguish provider configuration/auth/credit/rate-limit/unavailability/request/response/model failures, empty/truncated/oversized output, timeout, and interruption. Provider bodies, exception causes, and caller abort messages are not attached to these errors.

## Repair and evaluation seam

`ComposeGenerator.generateValidated` accepts a validator callback and permits one complete replacement after a typed `ComposeValidationFailure`. Feedback uses fixed policy categories and static text; it never forwards parser exception messages, YAML fragments, arbitrary feedback, or the previous untrusted document. A second validation failure ends generation. Provider failures and unexpected validator exceptions do not trigger a content repair. The product maximum is two content responses, each with at most three HTTP attempts, within one five-minute deadline. Returned successful results retain both response metadata objects. Step 4 uses an awaited capture callback to encrypt every complete response before validation, including rejected responses when repair fails.

The [terminal evaluator](evaluation/terminal-runner.md) calls `ComposeGenerationProvider.generate` directly and scores its first complete response, without invoking repair orchestration. Transient transport retries remain bounded and are counted; they do not repair model content. The ten-case CLI and file reports are implemented; no live model-quality score has been measured yet.
