# Direct Compose validation and persistence

Steps 4–5 are integrated. All newly admitted jobs use OpenRouter, strict YAML/policy validation and exact model-authored persistence. [Saved execution](saved-compose-runtime.md) reuses the validator in admission, runner and terminal paths. The creation capability is enabled; version 1 generation/compiler/runtime branches are removed.

## Validation boundary

`validateCompose(compose, requirements)` accepts the original string and server-issued requirements. It returns that same string, its UTF-8 SHA-256 digest, and inspection metadata. It never serializes a document, inserts defaults, fixes fields, or calls the legacy parser/compiler. Missing settings require the one model repair or a failed attempt.

The pinned `yaml@2.9.1` parser uses strict YAML 1.2 core semantics with silent diagnostics and no merge handling. The validator rejects blank/oversized input, invalid Unicode/NUL, multiple documents, parser errors/warnings, duplicate or nonstring keys, directives, explicit tags, anchors, aliases, and merge keys. AST conversion has a 64-level and 20,000-node limit and builds mappings without prototypes. Parser errors and source excerpts never enter logs, status responses, or repair requests. See the [parser API and options](https://eemeli.org/yaml/) and [pinned release](https://github.com/eemeli/yaml/releases/tag/v2.9.1).

The complete [version 2 policy](compose-policy.md) is enforced recursively: exact project/service identities, pinned images, ownership labels, private bridge network, resource/logging/capability settings, absence of published ports, database mounts/volumes, health-check structure/timings, known environment bindings, and acyclic healthy-service dependencies. Unknown fields fail at every level. Inputs are rechecked for catalog consistency, valid identities, required database bindings, assignment uniqueness, and limits before provider use.

Every declared binding must appear exactly as its assigned `${DIC_SECRET_<reference>:?Required value}` string. MySQL defaults are `MYSQL_DATABASE` from the request or `app`, and `MYSQL_USER: app`. MongoDB defaults are the requested database or `app`, and root username `app`. An explicit supplied binding may replace a public default. All other literal environment settings and inherited or undeclared variables are rejected. Container names such as `PATH`, `DOCKER_HOST`, and `__proto__` remain ordinary mapping keys; they do not become host process settings.

Commands are optional nonempty string argument arrays. Every service requires a health check with `CMD` plus arguments or `CMD-SHELL` plus one expression. Container dollars must use `$$`; secret interpolation is permitted only in assigned environment entries. Obvious installer/downloader commands are rejected, including split argument arrays. Static validation cannot prove the behavior of arbitrary in-image programs or the truth of a model-authored health check. Runtime observation and the independent task probes in the evaluation remain necessary. This policy is for trusted users on the dedicated host, not hostile multi-tenant execution.

`validateSavedCompose` first verifies the revision envelope, owner/config/revision/project identity and digest, then validates the complete YAML and compares newly derived service/environment metadata. Altering metadata does not authorize execution. The runner, admission and terminal paths now call this check. Database binding order is normalized for comparison; references, purposes and assignments must match exactly.

## Durable generation

`GenerationWorker` retains its two durable global slots, per-user admission, encrypted inputs, ownership checks, queue expiry, lease fencing, shutdown cancellation, crash cleanup, and initial immutable revision. Only version 2 jobs are claimed; legacy queue expiry/recovery and artifact cleanup are excluded. The supplied-value capability is enabled after step 5 integration; no legacy provider or compiler remains.

Before inference, the decrypted requirements must match the job's server identity, stored service selection, and configuration-scoped supplied-value reference/purpose/binding rows. No actual supplied values are needed or decrypted by generation. There is no generated-password stage on this path.

`ComposeGenerator` awaits an encrypted capture callback for each complete provider response before validation. Capture includes the first rejected document even if repair fails. At most two strings of at most 1 MiB each are retained. Internally, `outputEncrypted` contains an AES-GCM-encrypted JSON array of base64 UTF-8 strings, scoped to the generation ID. Encoding before encryption bounds the database size even for rejected control-character content; the encrypted field stays below 4 MiB. Oversized injected test responses are truncated for capture, marked `outputTruncated`, and rejected without repair. Actual transport overflow/truncation is rejected by the adapter without retaining its HTTP body.

Migration `20261105010000_compose_generation` adds provider, requested model, and nullable response metadata to generation attempts. Enqueue records `openrouter` and the exact free-model identifier for version 2; legacy rows retain `fake`. Private response metadata records actual reported model, elapsed time, HTTP attempts, and available token usage for each complete response. Public status responses expose only safe provider/model/version/status/error fields and continue to report `runtimeValidation: not_performed`. Captures and private response metadata are not returned.

Publication locks the configuration row, verifies it remains undeleted, and fences success by status, lease token, unexpired lease, and the durable generation deadline. The transaction writes the exact accepted string through the existing private temporary-file/flush/rename protocol and saves the same string/digest with derived version 2 metadata. No procedural Compose generation or runtime operation is invoked. Failed publication rolls back the revision and removes its file or records cleanup for retry. Late responses cannot publish after cancellation, lease revocation, deletion, or the deadline. No supplied values appear in the saved Compose or metadata.
