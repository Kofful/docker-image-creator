# Saved Compose execution

Step 5 integrates the version 2 generation and execution paths. Creation now requires `inputVersion: 2`, both environment arrays, and all required database password assignments. The authenticated input capability is enabled. The [OpenAI-compatible adapter](openai-compatible-adapter.md) is the generation provider; the procedural compiler, fake provider, runtime renderer, and generated-password path are removed. Missing `OPENAI_BASE_URL`, `OPENAI_API_KEY` or `OPENAI_MODEL` fails generation explicitly. No model request is made during application startup.

## Execution boundary

`runtime.manifest.ts` now reads and validates saved revisions; it never constructs Compose. Start admission, runner execution/reconciliation/deletion, service observations, and terminal authorization/cleanup share this boundary. It checks version, ownership, exact digest, YAML/policy, selected services, and references against independently stored service and binding records. Binding order is immaterial; assignment, purpose and reference changes are rejected. An unchanged digest alone cannot authorize changed policy or derived metadata.

Deployment `manifest` and `digest` columns retain their names but now hold an exact copy of the accepted revision, rather than a separately generated execution document. The runner checks deployment equality with that revision and validates again at the privileged Start boundary. Pull and Up receive the original string on stdin, with fixed executable/argument arrays, an empty private project directory and explicit `--env-file /dev/null`. No defaults, commands, health checks, labels or volumes are inserted into the document. Model health checks are untrusted behavior; independent task evaluation belongs to step 6.

Only Start selects/decrypts supplied-value ciphertext. The other runtime and terminal readers select reference/purpose/assignment metadata. Decryption uses configuration/reference-bound authenticated context; values must still satisfy the input byte/Unicode limits. The child environment contains fixed runner `PATH`/`DOCKER_HOST`, `COMPOSE_DISABLE_ENV_FILE=1`, and exactly the required `DIC_SECRET_<hex>` keys. Container bindings called `PATH` or `DOCKER_HOST` consume opaque references and cannot override runner settings. Provider keys, session credentials and arbitrary host variables are never inherited. Values are passed directly in process memory, without a secret file or shell interpolation.

The explicit environment selection follows Docker's [interpolation rules](https://docs.docker.com/reference/compose-file/interpolation/) and [environment-file controls](https://docs.docker.com/compose/how-tos/environment-variables/envvars/). Container-dollar expressions remain escaped as `$$` in the authored artifact. Supplied values are not reinterpreted as Compose text.

Inspection uses validated metadata and policy 2 ownership labels. The existing private bridge, image/resource/mount checks, durable reservations, operation deadlines, concurrent admission, rollback, and terminal reauthorization remain in effect. Stop preserves named volumes. Delete removes only verified stopped containers, their private network and owned artifacts, retaining named volumes and encrypted recovery metadata.

## Private networking and supplied-value limits

Real Docker testing exposed that the required internal isolated bridge does not publish loopback ports. On 2026-11-05 the user chose to retain isolation and reject publication. Creation now rejects `hostPort`, the prompt forbids `ports`, and validation rejects all published mappings. Runtime observations never advertise a published endpoint. Use service DNS within the stack and authenticated container terminals. This supersedes earlier loopback publication requirements without weakening network isolation.

Value delivery and image initialization are separate concerns. The stock MySQL entrypoint interpolates passwords into SQL and a client option file; arbitrary quotes/backslashes can break its initialization even when Compose delivered the value exactly. See the [upstream entrypoint](https://github.com/docker-library/mysql/blob/master/8.4/docker-entrypoint.sh). The lifecycle fixture uses compatible database credentials, tests dollar/hash/space preservation there, and separately round-trips quotes, backslashes and line breaks through Node plus a shared database binding. It does not establish arbitrary-password compatibility of every model program. Evaluation case C09 remains unchanged and independently measures that behavior; failures must be counted, never rewritten into different values.

## Legacy cutoff and deployment

There is no legacy execution or conversion branch. Version 1 Start, observations, terminal tickets and cleanup are rejected. Generation/runtime workers exclude legacy jobs from claiming, expiry sweeps and reconciliation; legacy artifact cleanup is excluded too. Retained records, artifacts and volumes are not automatically deleted or relabelled.

Before deploying this version, use the previous version to stop legacy workloads/terminals, finish cleanup, and drain old generation/runtime jobs and reservations. Then apply all nine committed migrations and replace API, web and runner together. Operator-managed infrastructure passes `OPENAI_BASE_URL`, `OPENAI_API_KEY` and `OPENAI_MODEL` only to API generation and runner evaluation. Agents do not load protected environment files. `CONFIG_FAKE_DELAY_MS` no longer exists. No application deployment, credential configuration, legacy-resource cleanup or live inference is implied by source verification.
