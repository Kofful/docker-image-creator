# Direct Compose contract, version 2

Step 1 of the [implementation plan](llm-compose-plan.md) is implemented: shared types, a revision envelope gate, policy constants, and a hand-authored fixture. The current API, fake generator, and runner still use version 1. Version 2 is not activated. Steps 2–4 now add supplied-value input, the provider adapter, and gated [YAML validation/persistence](compose-validation.md). Runner integration remains step 5. Policy constants or a valid envelope alone never authorize execution.

## Transport and persistence

The new types live in `packages/contracts/src/compose.ts`. They are exported separately from the existing endpoint types so unfinished version 2 requests cannot silently enter version 1 endpoints.

- `CreateComposeConfigRequest` adds `inputVersion: 2`, private `environmentValues`, and `environmentBindings` to the existing creation fields. A value has a request-local `key`, its actual `value`, and a `purpose`. A binding names its `service`, container environment `name`, and `valueKey`. Multiple bindings can refer to one value. Step 2 implements [validation, encrypted persistence, and gated UI submission](supplied-environment.md); activation waits for generation/runner integration.
- `ComposeGenerationRequirements` contains service selections, instructions, server-issued identities, and `ComposeEnvironmentReference` entries. References contain only an opaque interpolation name, purpose, and service/name bindings. Actual values and request-local value keys are excluded from this provider contract. Step 3's [adapter](openrouter-adapter.md) constructs this payload explicitly rather than spreading a creation request into a prompt.
- `ComposeGenerationResponse` identifies OpenRouter and the exact accepted model while retaining safe status fields. Existing responses still identify the fake provider until integration.
- `ComposeRevisionMetadata` has `format: llm-compose`, `schemaVersion: 2`, `policyVersion: "2"`, `catalogVersion: 1`, `identity`, `services`, and `environment`. Persist it alongside the exact Compose string and lowercase SHA-256 digest. Metadata describes validated images, ports, mounts, and references for inspection; it never supplies a new executable document.

`composeIdentity` requires server-issued UUIDs and sets project name to `dic-<configId>`. `readComposeRevisionCandidate` rejects legacy/unknown versions, unknown envelope fields, ownership/revision/project mismatches, blank/oversized documents, and digest mismatches. It preserves all document bytes. Its returned service/reference metadata remains `unknown` until `validateSavedCompose` derives and compares it. A valid header or matching digest alone never permits Docker execution.

Existing version 1 data is unsupported by this new gate. It is not converted or deleted. Production switches only once generation, validation, and runtime integration are ready, following the operator cutoff in the plan.

## Required YAML subset

`apps/api/src/configs/compose.policy.ts` holds versioned allowlists and exact required settings. The implemented provider prompt includes these settings and server identities before generation. Missing settings require repair/failure; the application must not inject defaults into generated YAML.

The validator now enforces the following before saving version 2 revisions. Step 5 must invoke it again before execution:

| Area         | Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Parsing      | One UTF-8 YAML document, at most 1 MiB; reject duplicate keys, aliases, anchors, merge keys, custom tags, code fences, non-mapping root, and unknown fields at every level. JSON-shaped YAML may parse but no intermediate JSON service specification is generated.                                                                                                                                                                                                                                                                                      |
| Identity     | Exact server project name; exact requested service set (1–4), catalog image/tag, database settings, and requested ports. No model-chosen resource names, additional services, or image substitutions.                                                                                                                                                                                                                                                                                                                                                    |
| Catalog      | Node `node:22.23.4-bookworm-slim`:8000; Python `python:3.13.18-slim-bookworm`:8000; MySQL `mysql:8.4.11`:3306; MongoDB `mongo:8.0.17`:27017. The catalog is independent of generation; no compiler remains.                                                                                                                                                                                                                                                                                                                                              |
| Containers   | Require `init: true`, `restart: "no"`, `networks: [stack]`, `cap_drop: [NET_RAW]`, `cpus: 0.5`, `mem_limit: 512m`, `pids_limit: 128`, and `json-file` logging with `max-size: 5m`, `max-file: "2"`. No extra capability, host namespace/network, device, bind mount, build, profile, hook, include, extension field, socket, or env file.                                                                                                                                                                                                                |
| Labels       | Containers require managed=`runtime`, user/config/revision IDs, and policy=`2` under the `docker-image-creator` prefix. Network/volume labels omit revision so their identity survives future revision replacement; all other ownership fields match exactly. Additional model-chosen labels are rejected.                                                                                                                                                                                                                                               |
| Network      | Exactly one `stack` bridge, `internal: true`, `enable_ipv6: false`, with `com.docker.network.bridge.gateway_mode_ipv4: isolated` and ownership labels. No external network, custom network name, additional driver options, or implicit default network.                                                                                                                                                                                                                                                                                                 |
| Ports        | No published ports. Creation rejects `hostPort`; Compose validation rejects every `ports` field, including loopback mappings. User accepted this on 2026-11-05 after real Docker testing showed internal isolated bridges do not publish ports. Use private-network access and authenticated terminals.                                                                                                                                                                                                                                                  |
| Storage      | Only required database named volumes: `<service>-data` at `/var/lib/mysql` for MySQL or `/data/db` for MongoDB, plus `<service>-configdb` at `/data/configdb` for MongoDB. Long mount syntax with `type: volume`, exact `source`/`target`, `read_only: false`. Each top-level volume has ownership labels only. No unused/extra volume, external volume, explicit global name, driver options, anonymous volume, or application mount.                                                                                                                   |
| Environment  | String-to-string mapping only. Every declared user binding must use its assigned `${DIC_SECRET_<32 lowercase hex>:?Required value}` exactly; all names/references/assignments must be known. Server-issued interpolation names never derive from container keys such as `PATH` or `DOCKER_HOST`. Catalog database/user defaults may be literal public settings; other literal values must be validated against request metadata. Secret values stay encrypted and outside this document. No environment inheritance or undeclared variable substitution. |
| Commands     | Optional nonempty argument arrays of strings; no entrypoint override. The model authors behavior using tools/libraries already in the image, without package installation/downloads or companion files. Container commands remain untrusted and are never host shell commands. This is a trusted-user execution policy, not a hostile-code sandbox.                                                                                                                                                                                                      |
| Health       | Required on every service, with only `test`, `interval`, `timeout`, `retries`, `start_period`. Test is `CMD` plus arguments or `CMD-SHELL` plus one container-shell expression. Require interval/timeout `5s`, retries `24`, start period `10s`. No disabled checks; runtime verifies observed health, and evaluation independently verifies task behavior.                                                                                                                                                                                              |
| Dependencies | Optional mapping to other requested services with only `condition: service_healthy`. Reject self-reference and cycles. No restart/required overrides.                                                                                                                                                                                                                                                                                                                                                                                                    |

In command/health strings, `$$` escapes a container-side dollar sign. All Compose substitutions must be approved opaque references; unescaped arbitrary variables, defaults, and references in resource identities are rejected. Inject the corresponding values only into the restricted runner interpolation environment, keeping container environment names independent of host process settings. Step 2 must prove exact preservation of special characters.

## Fixtures and verification boundary

`apps/api/test/fixtures/direct-compose.yaml` is a hand-authored Node example with exact labels, isolation settings, and one opaque environment binding. It is used to prove byte preservation through the envelope gate; it is now accepted by the strict validator, alongside a frozen four-image fixture; this does not prove healthy execution.

Step 4 tests these positive fixtures and individual image subsets against the complete policy. Required negative fixture families are malformed/duplicate/multiple YAML documents; aliases/tags/merge keys; extra fields at every nested level; image substitution; unsafe mounts/build/devices/capabilities/host access; network/label/port changes; missing resource/log limits; unknown/misassigned interpolation; and cyclic dependencies. They are separate from the ten generation evaluation cases and must run without provider calls or Docker.

Run `pnpm test:compose-contract` for envelope/integrity tests and `pnpm test:compose-validation` for the strict YAML/policy tests without MySQL, Docker, credentials, or environment-file loading. The checks prove fixture policy acceptance/rejection, not healthy startup or model evaluation scores.

The syntax choices follow the official [Compose services reference](https://docs.docker.com/reference/compose-file/services/) and [network reference](https://docs.docker.com/reference/compose-file/networks/); this application's subset is deliberately narrower.
