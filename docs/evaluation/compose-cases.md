# Ten fixed evaluation cases

Inputs/probes live in `apps/api/evaluation/cases.ts` and `driver.ts`. These are tasks, not supplied Compose answers. Each gets the same policy/catalog, fresh server identities and opaque bindings; private disposable values remain in memory. All services must satisfy health/resource/network policy before independent assertions.

| ID  | Services                              | Independent task assertions                                                                                                                                                                            |
| --- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| C01 | `web`: Node.js                        | Port 8000 `/healthz` → 200; `/message` returns exact supplied `APP_MESSAGE` as UTF-8 text, without extra newline/JSON quoting.                                                                         |
| C02 | `web`: Python                         | Same HTTP health/message contract as C01.                                                                                                                                                              |
| C03 | `db`: MySQL                           | Requested `orders` database; supplied application/root credentials authenticate; application `SELECT 1`; wrong password rejected.                                                                      |
| C04 | `db`: MongoDB                         | Supplied `app` root user authenticates against `admin` and pings; wrong password rejected; requested database environment setting matches. Empty database need not exist before first write.           |
| C05 | `web`: Node.js, `db`: MySQL           | DNS/TCP to `db:3306`; `/ready` succeeds only while reachable and fails after database stop; independent MySQL authentication/query; shared password reaches both declared bindings.                    |
| C06 | `web`: Python, `db`: MongoDB          | DNS/TCP to `db:27017`; readiness fails after database stop; authenticated MongoDB ping; shared password reaches both bindings.                                                                         |
| C07 | `gateway`: Node.js, `backend`: Python | Gateway `/backend` retrieves exact supplied message from `http://backend:8000/message` by service DNS, without published ports.                                                                        |
| C08 | `sql`: MySQL, `documents`: MongoDB    | Distinct supplied credentials reach each database; independent query/ping succeeds, wrong passwords fail; no publication.                                                                              |
| C09 | `db`: MySQL                           | Exact password containing dollars, quotes, backslashes, spaces and `#`; authentication and environment comparison; inserted marker survives Stop/Start of the same artifact/volume without generation. |
| C10 | Node.js, Python, MySQL, MongoDB       | All remain healthy; HTTP and authenticated database probes pass; both apps resolve/connect to both databases; values reach intended bindings.                                                          |

Node/Python use shipped standard libraries, without dependency installation or downloads. DNS/TCP readiness and independent authenticated database probes are separate assertions; application database-client implementations are not required. Probes use verified service identities and trusted programs, not model health checks. Secret comparisons emit only pass/fail and never reveal values in HTTP/arguments/reports.

These ten are positive workload cases. Malicious YAML, prompt injection, unsafe fields/host access and policy/secret bypass are covered by separate deterministic rejection suites and do not enter this denominator.
