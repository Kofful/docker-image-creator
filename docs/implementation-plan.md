Milestone 4 design accepted (2026-11-05): direct LLM-authored Compose through the specified free OpenRouter Gemma model, creation-time supplied secret/environment values and shared bindings, and one product repair without fallback. Existing template-generated configurations are unsupported; no conversion or backward-compatible execution is required, and legacy data is not implicitly deleted. General revision editing/history/export and secret rotation remain deferred. The ten-case evaluation is testing only: a terminal command prints all results and writes report files without database persistence; policy acceptance, healthy startup, and task success are scored on first responses. The [milestone plan with seven verifiable steps](llm-compose-plan.md), [evaluation design and ten cases](llm-compose-evaluation.md), and [accepted ADR 0004](adr/0004-direct-llm-compose-generation.md) are the source of truth for this slice. ## Console milestone (2026-11-03)

The user approved the [terminal behavior](terminal-api.md): per-running-container Connect opens a same-tab page, uses Bash then sh under the container's configured permissions, and returns to configuration detail on exit/disconnect or connection/authorization failure without stopping the main service or reconnecting automatically. Deliberately detached jobs may continue. No host shell exists behind the exec connection; real container escapes are not reliably detectable UI events. The user explicitly rejected terminal idle timeouts, maximum durations and connection-count quotas. Authentication expiry, workload resource policy, bounded transport/scrollback and protocol liveness remain.

The implementation includes migration `20261103010000_terminal_tickets`, owner/session/applied-deployment-bound one-use ticket issuance, exact WebSocket Origin checks, the API relay, private ticket-authenticated runner transport, Engine TTY streaming/resize, and verified shell/foreground cleanup. `TERMINAL_RUNNER_URL` selects the private relay target. API and runner must be rebuilt with the migration; Nginx/Vite must include upgrade proxy support. Graceful runner shutdown waits for setup/cleanup; forced termination, daemon outage or user removal of cleanup tools may leave exec processes until Stop. Full milestone 5 workload/network/volume verification and a deployed browser end-to-end test remain separate gates.

Acceptance: the final disposable MySQL/Docker suite passed 99 checks with one older-Engine check skipped on Engine 28.1.1; all seven migrations applied and replayed successfully. Real terminals proved input/output/resize, exit/Ctrl+D, explicit disconnect and lost-transport shell/foreground cleanup, independent concurrent connections, logout/absolute session expiry, ownership loss, container stop, Bash fallback and shellless failure. All 100 frontend tests passed, including no idle/duration timer and explained auth-ended navigation without private requests. Workspace type checking, ESLint without warnings, production web build, changed-source/document formatting, whitespace checks, and production/development Compose normalization passed. This verifies console source and its scoped integration gate; no application deployment, real-browser end-to-end run, or complete catalog/network/volume smoke was performed.

## Test strategy

The auth suite exercises HTTP endpoints against a fresh MySQL 8.4.11 container. It covers normalization, duplicate registration (including concurrent requests), generic login failures, strict payload validation, successful refresh, replay and concurrent refresh, access/session expiry, JWT tampering and claim rejection, session-scoped logout, origin rejection, and rate limits. `pnpm test` builds the API, applies committed migrations twice, runs the suite, and removes only its generated test container and volumes. No SQLite or database mocks are used. All 24 endpoint tests passed against the disposable MySQL 8.4.11 image during the authentication UI change.

Use focused unit tests for compiler/policy/state transitions; API integration tests against disposable MySQL for transactions and ownership; frontend component tests for meaningful validation/error behavior; Playwright for core browser flows; and opt-in integration tests against an explicitly designated Docker daemon. Avoid paid model calls in CI. Use a fake for deterministic coverage and a manual real-provider smoke test before declaring generation integration complete.

Docker tests must use unique project labels, bounded resources, and scoped cleanup. Never run destructive checks against unrelated containers or volumes. Do not replace failed real database/Docker verification with mocks and claim integration success.
