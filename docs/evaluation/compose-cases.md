# Ten Compose generation evaluation cases

Status: case mix accepted in Q8 on 2026-11-05 for the [terminal evaluation](../llm-compose-evaluation.md). These are ten task definitions, not generated results; executable fixtures/probes remain to be implemented. No expected Compose document is synthesized or supplied to the model.

Each case receives the same versioned execution-policy contract, exact approved image tags, server-owned resource identities, and service/environment bindings. All services require meaningful health checks, supported resource limits, and one private configuration network. No custom images, downloaded packages, adjacent source files, external network access, or host publication are required. Application behavior uses the libraries already included in the Node/Python images.

Fixture value descriptions below instruct the future evaluator to create disposable test values in memory. Never use real credentials, expose supplied values to the model, or return them in reports. The evaluator knows the expected values for private comparisons. Database negative-auth checks use a deliberately incorrect test password and must be bounded.

| C03 | MySQL with a requested database and supplied credentials | `db` (MySQL)                                                              | Requested `orders` database exists; user `app` authenticates with the supplied application password and executes `SELECT 1`; incorrect password fails; a separate supplied root password is configured.                                                                                             |

| C10 | Full four-service configuration                          | `node` (Node.js), `python` (Python), `sql` (MySQL), `documents` (MongoDB) | All four services remain healthy together; independent HTTP probes, MySQL authentication/query, and MongoDB authentication/ping pass; both applications can resolve and establish TCP connections to the two database services; declared supplied environment values reach their intended services. |

For C05, C06, and C10, TCP reachability and authenticated database probes are separate assertions. These cases do not claim that a standard-library-only Node/Python application implements a full database client. Application-level SQL/MongoDB queries would require separately deciding how client dependencies are supplied under the no-install policy.

The evaluator must check probes itself using trusted code and verified service identities; a command authored by the model is not an independent assertion. For C09, interpolation must preserve literal input values rather than reinterpreting them as Compose syntax. Secret comparisons return only pass/fail; secret values must not appear in HTTP responses, command arguments, or reports.

These ten are positive workload cases. Malicious YAML, prompt injection, unknown fields, privileged mode, host access, secret leakage, and resource-policy bypass belong in a separate deterministic rejection suite, where rejection is the expected result. Do not mix those expected rejections into the ten-case healthy-start denominator.
